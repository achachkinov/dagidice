# Операционный протокол OpenCode (Quartz 5 + Obsidian)

1. **Инструменты IDE, Node.js и кодировка (Windows):**
   - **Точечные операции (1–5 файлов):** использовать нативные инструменты OpenCode (`read`, `edit`, `write`, `glob`, `grep`).
   - **Массовые операции (анализ всей базы, статистика, однотипные замены в 10+ файлах):** использовать временный скрипт на **Node.js** (`node _tmp_task.mjs`) со строгой кодировкой `'utf8'` (`fs.readFileSync(..., 'utf8')`), после выполнения сразу удалять скрипт (`Remove-Item _tmp_task.mjs`).
   - **Запрещено:** использовать PowerShell (`Get-Content`, `Set-Content`, `Add-Content`) для чтения или записи Markdown-файлов без явного `-Encoding UTF8` (ломает кириллицу).

2. **Git и защита инвариантов разметки:**
   - Работать в текущей ветке, НЕ делать `git commit`.
   - **Read-Only зона (каркас):** В файлах `content/games/*.md` запрещено ломать синтаксис callout-блоков (`> [!cover]`, `> [!badges]`, `> [!actions]`) и формат ссылок `[[base/имя.base|имя]]`. Допускается только замена класса цвета у бейджа игроков (`badge-green` / `badge-orange` / `badge-red`), корректировка списка тегов и текста.
   - **Синхронизация YAML:** При изменении `description:` во frontmatter обязательно приводить его к 1-му абзацу секции `### Коротко об игре`.
   - **Запрещено трогать** `content/base/*.base` и `content/all-tags.md` при добавлении отдельной игры. Также запрещено переписывать существующие `content/games/*.md` вне рамок текущей задачи.

3. **Добавление новой игры (эталон — `content/templates/GAME.md`):**
   - **Имя файла:** русское название → дефисы вместо пробелов (`Битва-за-Рокуган.md`); латиница — как есть (`Radlands.md`); символы `:`, `!`, `.`, `,`, `?` из имени убирать.
   - **Frontmatter (строго):**
     ```yaml
     ---
     title: <Название игры>
     tags:
       - <тег-1>
       - <тег-2>
     type: game
     image_url: <прямая ссылка на обложку>
     description: <1-й абзац из «Коротко об игре»>
     ---
     ```
   - **Порядок секций (не менять):** `> [!cover]` → `> [!badges]` → `> [!actions]` → `### Теги` → `### Коротко об игре` → `---` → `### 🎬 Видео-правила`.
   - **`### Теги`:** та же выборка тегов, что и во frontmatter, в формате `[[base/тег.base|тег]]` через пробел. Ставить ТОЛЬКО ссылки на реально существующие файлы `content/base/*.base`.
   - **`### Коротко об игре`:** 2–4 предложения; первый абзац ДОСЛОВНО дублируется в `description:`.
   - **Обложка:** `image_url` и `[!cover]` используют один и тот же URL. Если за 2 запроса обложку/данные найти не удалось — ставить в `image_url` и в `[!cover]` маркер `[ПРОВЕРИТЬ ВРУЧНУЮ]`.
   - **YAML и двоеточия:** двоеточие в `title:`/`description:` ломает frontmatter (`bad indentation of a mapping entry`). НЕ оборачивать значения в кавычки — заменять `: ` на длинное тире ` — ` (например `Civilization — Новый рассвет`, `действий — исследуют`). При этом `description:` синхронизировать с 1-м абзацем «Коротко об игре».

4. **Таксономия и техгигиена (строгие правила):**
   - **Источник тегов:** только список из `content/all-tags.md` (39 тегов). Новый тег запрещено вводить без правки `content/base/generate.py` + `content/all-tags.md` и перегенерации `.base`-файлов.
   - **Цвет бейджа игроков:** Строго по максимальному числу игроков: `badge-green` (`<= 4`), `badge-orange` (`5–6`), `badge-red` (`7+`).
   - **Склонение числа игроков:** `1 игрок`, `2 игрока`, `3-6 игроков`, `7+ игроков`.
   - **Тег `дуэльная`:** Ставить ТОЛЬКО играм строго на 2 игроков (`2 игрока`). Для игр на `2–4` этот тег запрещен.
   - **Видео-правила:** Только прямые ссылки на ролик (`https://youtube.com...` или `https://youtu.be...`). Запрещены плейлисты (`/playlist?`), `/live/` и пустые плейсхолдеры.
   - **Внутренние ссылки** `[[Файл|Название]]` ставить ТОЛЬКО на реально существующие файлы в `content/games/`.

5. **Сетевые запросы (`webfetch`) и фактчекинг (Anti-Loop):**
   - **Категорически запрещено** скрейпить через `webfetch` HTML-страницы поисковиков (`://google.com`, `bing.com`, `duckduckgo.com`, `brave.com`, `://youtube.com`).
   - Для проверки фактов или поиска обложки/описания разрешено не более **2 запросов `webfetch` на одну игру** по прямым карточкам на `tesera.ru`, `boardgamegeek.com` или `hobbygames.ru`. Если данные не найдены за 2 попытки — поставить маркер `[ПРОВЕРИТЬ ВРУЧНУЮ]` и идти дальше.

6. **Бюджет контекста и батчинг:**
   - Для массового обогащения текстов работать батчами по **5–8 файлов** (или через субагентов), читая только `AGENTS.md`, эталон `content/templates/GAME.md` и целевые файлы текущего батча. Не загружать все 83 файла целиком в контекст LLM.

7. **Проверка сборки:**
   - Запускать `npx quartz build` **один раз** в самом конце работы после завершения всех правок (не гонять сборку после каждого файла).

8. **Формат итогового отчета (строго 3 блока без воды):**
   - **Что сделано и как проверить:** сводка изменений (`git diff --stat`) и пункты для ручной проверки в браузере.
   - **Следующий шаг и модель:** рекомендуемый режим и модель (`DeepSeek V4 Pro` для шаблона/архитектуры или `DeepSeek V4.1 Flash` для пакетного контента).
   - **Технические грабли:** найденные аномалии в файлах (если были) в 1–2 строки.

9. **Стоп-кран при противоречиях (Circuit Breaker):**
   - ЗАПРЕЩЕНО искать обходные пути в блоке размышлений, если два условия противоречат друг другу или затрагивают запрещенный файл.
   - При обнаружении конфликта НЕМЕДЛЕННО прекрати рассуждения и выведи ТОЛЬКО шаблон:
     `[КОНФЛИКТ ПРАВИЛ]: <суть в 1 предложении>. Вариант А: <...> / Вариант Б: <...>. Жду выбора.`
